# InternTrack production deployment guide

This guide targets a conventional Linux server running Nginx or Apache, PHP-FPM, MySQL 8 and a queue worker. Commands assume the application lives at `/var/www/interntrack` and the web/PHP user is `www-data`; adjust them to your environment.

## 1. Server requirements

- PHP 8.2 or newer with `pdo_mysql`, `mbstring`, `openssl`, `fileinfo`, `dom`, `xml`, `curl`, `tokenizer`, `ctype` and `gd`
- Composer 2
- MySQL 8 with `utf8mb4`
- Node.js 20+ and npm for building front-end assets
- Nginx or Apache, HTTPS certificate, a process supervisor (systemd or Supervisor)
- Writable `storage/` and `bootstrap/cache/`

## 2. Database

Create a dedicated database and user. Use a long, unique password generated by a password manager; do not reuse the local development credentials.

```sql
CREATE DATABASE interntrack CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'interntrack_app'@'localhost' IDENTIFIED BY '<strong-random-password>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
    ON interntrack.* TO 'interntrack_app'@'localhost';
FLUSH PRIVILEGES;
```

Migrations need DDL rights. After a release you may remove `CREATE`, `ALTER`, `INDEX`, `DROP` and `REFERENCES` until the next migration, but leave the runtime DML rights. Grant `LOCK TABLES` and `PROCESS` if your backup tool requires them.

## 3. Application setup

```bash
cd /var/www
# place the release in /var/www/interntrack
cd interntrack
composer install --no-dev --optimize-autoloader --no-interaction
cp .env.example .env
php artisan key:generate
```

Set production values in `.env`:

```dotenv
APP_NAME=InternTrack
APP_ENV=production
APP_DEBUG=false
APP_URL=https://internships.example.ac.ug
APP_TIMEZONE=Africa/Kampala
LOG_CHANNEL=stack
LOG_LEVEL=warning

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=interntrack
DB_USERNAME=interntrack_app
DB_PASSWORD=<strong-random-password>

SESSION_DRIVER=database
SESSION_SECURE_COOKIE=true
SESSION_HTTP_ONLY=true
SESSION_SAME_SITE=lax

CACHE_STORE=database
QUEUE_CONNECTION=database
FILESYSTEM_DISK=local

MAIL_MAILER=smtp
MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_SCHEME=tls
MAIL_USERNAME=<smtp-user>
MAIL_PASSWORD=<smtp-password>
MAIL_FROM_ADDRESS=internships@example.ac.ug
MAIL_FROM_NAME="${APP_NAME}"
```

Then run migrations and base seed data:

```bash
php artisan migrate --force --seed
php artisan storage:link
npm ci
npm run build
php artisan optimize
```

`DatabaseSeeder` always installs roles, system settings and the academic structure. `DemoDataSeeder` detects `APP_ENV=production` and refuses to run, so no demo accounts or demo passwords are created. Adjust the seeded university profile, faculties, departments, courses and periods in the admin UI before onboarding real users.

### Create the first administrator

There is deliberately no default production password. After roles are seeded, create the first administrator interactively:

```bash
php artisan tinker
```

```php
$roleId = App\Models\Role::where('name', 'admin')->value('id');
$password = Illuminate\Support\Str::password(24);
App\Models\User::create([
    'name' => 'System Administrator',
    'email' => 'admin@example.ac.ug',
    'password' => $password,
    'role_id' => $roleId,
    'status' => App\Enums\UserStatus::Active,
]);
$password;
```

Copy the generated password from the final line and deliver it over a secure channel. Do not paste passwords into tickets, chat history or Git. Sign in, change the password from the profile page, and create the remaining staff accounts through the admin UI or CSV import.

### File permissions

```bash
sudo chown -R www-data:www-data storage bootstrap/cache
sudo find storage bootstrap/cache -type d -exec chmod 775 {} \;
sudo find storage bootstrap/cache -type f -exec chmod 664 {} \;
sudo chmod 640 .env
```

Ensure `storage/app/private` is not inside the web root. Evidence is served only through authenticated, policy-checked routes.

## 4. Web server

### Nginx

```nginx
server {
    listen 80;
    server_name internships.example.ac.ug;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name internships.example.ac.ug;

    root /var/www/interntrack/public;
    index index.php;
    charset utf-8;

    ssl_certificate     /etc/letsencrypt/live/internships.example.ac.ug/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/internships.example.ac.ug/privkey.pem;

    client_max_body_size 12M;

    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location = /favicon.ico { access_log off; log_not_found off; }
    location = /robots.txt  { access_log off; log_not_found off; }

    location ~ /\.(?!well-known).* {
        deny all;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }
}
```

Verify the PHP-FPM socket path/version and reload Nginx.

### Apache

Enable `mod_rewrite` and `mod_headers`, set `DocumentRoot` to `/var/www/interntrack/public`, and allow `.htaccess` overrides (`AllowOverride All`). Enforce HTTPS with a redirect and set the same security headers. `public/.htaccess` is already included by Laravel.

## 5. PHP configuration

In the PHP-FPM `php.ini`:

```ini
upload_max_filesize = 12M
post_max_size = 12M
memory_limit = 256M
max_execution_time = 120
expose_php = Off
date.timezone = Africa/Kampala
```

The application rejects evidence above the configured limit (default 10 MB). Keep the PHP limits slightly higher than that application limit. If an administrator increases the upload limit in Settings, raise the PHP and web-server limits too. Reload PHP-FPM after changes.

Enable OPcache in production and restart PHP-FPM after each deployment.

## 6. HTTPS and sessions

- Serve the application only over HTTPS; set `APP_URL` to the HTTPS origin and `SESSION_SECURE_COOKIE=true`.
- If TLS terminates at a load balancer, configure trusted proxies in `bootstrap/app.php` so Laravel generates HTTPS URLs and secure cookies, and restrict direct access to PHP-FPM to the proxy. Do not blindly trust all proxies on a directly exposed server.
- Never expose `.env`, logs, `storage/`, `database/` or `vendor/` through the web root. The supplied Nginx root is `public/` and dotfiles are denied.
- Use a unique `APP_KEY` per environment and back it up with the application secrets. Changing it invalidates encrypted values and sessions.

## 7. Scheduler

Add the Laravel scheduler cron entry for the web user:

```cron
* * * * * cd /var/www/interntrack && php artisan schedule:run >> /dev/null 2>&1
```

Verify with:

```bash
php artisan schedule:list
```

The schedule runs attendance finalization, student reminders, supervisor digests and weekly risk alerts. Commands use `withoutOverlapping()` and reminders suppress duplicates. Ensure the server timezone is consistent with `APP_TIMEZONE`.

## 8. Queue worker

In-app notifications are always written synchronously. Email delivery is controlled by the notification settings and the mailer. If `QUEUE_CONNECTION=database`, run a worker so any queued work is processed and failed jobs are recorded.

Systemd example:

```ini
[Unit]
Description=InternTrack queue worker
After=network.target mysql.service

[Service]
User=www-data
Group=www-data
Restart=always
RestartSec=5
WorkingDirectory=/var/www/interntrack
ExecStart=/usr/bin/php /var/www/interntrack/artisan queue:work --sleep=3 --tries=3 --timeout=90
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now interntrack-worker
```

After deployment run `php artisan queue:restart` so workers load the new code. Monitor `php artisan queue:failed` and the `failed_jobs` table.

## 9. Backups and retention

Back up, encrypt and store off-server:

- daily MySQL dumps of `interntrack`
- `storage/app/private` (logbook and visit evidence)
- `.env` and `APP_KEY` in a secrets vault
- deployed release identifier/tag

Test a restore on a separate database and storage path at least quarterly. A common backup command is:

```bash
mysqldump --single-transaction --routines --triggers interntrack | gzip > interntrack-$(date +%F).sql.gz
```

Do not commit backups or `.env` files to Git.

## 10. Safe release procedure

```bash
cd /var/www/interntrack
php artisan down --retry=60
# deploy code and .env changes
composer install --no-dev --optimize-autoloader --no-interaction
php artisan migrate --force
npm ci
npm run build
php artisan optimize
php artisan queue:restart
php artisan up
```

Never run `migrate:fresh` or `db:wipe` on production, and never run the demo seeder. Take a database and storage backup before every migration. Keep the previous release available for rollback, and roll back code and database together when a migration changes the schema.

## 11. Security checklist

- `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL` on HTTPS
- unique database and SMTP credentials, not stored in Git or chat
- `SESSION_SECURE_COOKIE=true`, `SESSION_HTTP_ONLY=true`, `SESSION_SAME_SITE=lax`
- demo accounts absent; seeded university data reviewed
- least-privilege OS and database users; `.env` mode `640`
- no public access to storage, logs or dotfiles; evidence downloads policy-checked
- fail2ban/firewall and rate limiting at the edge in addition to Laravel throttles
- TLS certificate renewal and dependency updates monitored
- database, evidence and secrets backed up and restore-tested
- scheduler and queue worker running; failed jobs and application logs monitored
- the built-in `/up` health endpoint returns HTTP 200 and is monitored externally
- audit log access restricted to administrators

## 12. Post-deployment smoke test

1. Sign in as each role over HTTPS and confirm the role dashboard loads.
2. Create or confirm a placement with a company coordinate and radius.
3. Submit a check-in inside the radius and a logbook entry with evidence; confirm the files are not publicly reachable.
4. Approve the logbook as supervisor and confirm the student notification and dashboard state.
5. Generate a student PDF and the university report PDF.
6. Verify the scheduler list and run one reminder command in staging to confirm mail/in-app output.
7. Change a demo-free test setting, confirm the audit entry, and verify no secrets appear in responses or logs.
